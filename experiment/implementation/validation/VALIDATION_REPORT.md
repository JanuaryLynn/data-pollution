## 2026-09-22 Mac 启动适配

笔者实验时，因本机日志显示旧 `netlogo-headless.sh` 未能找到命令行 Java，随后在安装目录中也没有找到可执行的 `bin/java`。`console-launcher-v1` 因此加入了官方 `NetLogo_Console` 和 `--headless` 支持。后续本机日志明确显示，控制台从实验目录寻找 `NetLogo 6.4.0.app/Contents/app/NetLogo 6.4.0.cfg`，因启动目录不正确而失败。

因此，本包已进一步更新为 `console-launcher-v2`：两个 Python 入口都从 Console 所在的 NetLogo 安装目录启动子进程；模型、XML、CSV、日志仍通过绝对路径指向实验包。旧 `.sh` 路径保持原来的工作目录。校验失败时直接在结果中附上 `runtime_log_tail`，便于查看具体报错。

模型及 v1 校验脚本已在本环境通过原 `.sh` 路径的完整小批回归：38 次有效诊断和 5 项非法输入检查，历史记录保存在 `model_validation.json`，其中脚本哈希对应 v1；这不是 Mac 实测。v2 针对已出现的启动目录错误进行回归，Console 启动、相对配置读取、绝对数据路径及运行时记录的检查见 `console_launcher_validation.json`。`runner_execution_validation.json` 保留此前执行器端到端和断点续跑验证的历史证据；启动修复的当前版本证据单独保存，不将 Linux 适配器测试表述为 macOS 官方二进制测试。

Mac 需使用本版两个 Python 脚本，以 `/Applications/NetLogo 6.4.0/NetLogo_Console` 为启动路径重新执行本机校验，实际输出 `"status": "passed"` 后才算该机校验通过。
